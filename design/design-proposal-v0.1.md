# 产品设计提案 v0.1（已确认 2026-11-04）

> 依据：`research/wiki/synthesis.md` 第四节设计约束 P0-P7（全部有验证支撑）。
> 已确认决策：场景=读书/学习型；形态=CLI + MCP 工具先行（引擎优先，GUI 后续包壳）；技术栈=Python 3.12+ / uv；模型=BYOK 全兼容（OpenAI-compat 统一 + Anthropic 原生，不绑厂商）；许可证=Apache-2.0；命名=双语（英文 repo 名 + 中文产品名，具体名待定）。

## 1. 定位

**一句话**：读书人的复利知识库引擎——把读过的每本书、每篇论文编译成随取随用的知识资产，而非读后即忘的笔记堆。

**用户画像（分两步走）**：
- v1 用户：中文读书人/学习者中的极客先头部队——已在使用 Claude Code / Codex / Cursor / OpenCode 等终端 agent 的人（这正是 CLI/MCP 形态能触达的人群）
- v2+ 用户：全体中文读书人（同一引擎，GUI 壳）——**架构上从第一天就把"引擎"与"壳"分离**

**价值主张**（对应调研中验证的 wiki 赢面）：
- 跨书连接："这本书和那本书在 X 上的分歧"——检索结构上做不到，编译一次就存在于页面里
- 概念唯一真相源：一个概念一张卡，读第 N 本书时自动挂接前 N-1 本的理解
- 知识保鲜：快变领域（AI/行业）一手来源持续 ingest，胜过模型过期的预训练知识
- 学习留存：复习卡 + 可浏览渲染（graph view），"你不会看它就会抛弃它"

**差异化**（避免"又一个 CLI 编译器"同质化）：
1. 信任层产品化：封闭动作词表 + 逐字引用核验 + 人审队列——社区共识但无人完整交付
2. lint=决策队列：不是计数仪表盘，是可批量裁决的分诊 inbox
3. 渐进结构化：Pile→Database 路线内置（普通用户最重要的产品决策）
4. 中文读书领域 schema 模板："schema 是产品的 80%"（横评结论）
5. OKF v0.2 兼容：知识资产可携带，不锁死在本工具

## 2. 核心概念模型

### 2.1 Vault 分层（单向流，P3）

```
vault/
├── raw/            # 不可变原始层：书/PDF/EPUB/文章/转写（内容寻址，人写 LLM 读）
├── .kb/            # 可重建派生层：坐标索引、FTS 索引、待审队列（SQLite + JSON）
└── wiki/           # append-only 声明层：概念/人物/作品/主题页（LLM 写，人审）
```

- **单向流防火墙**：wiki 产出（origin: derived）永不当来源、排除出主索引——防自引用投毒（~1000 文件崩坏根因）
- index.md / log.md 降级为**可选兼容层**（多写者写热点，Dexio 已实测退役）；描述入 frontmatter，历史入页面历史
- 格式：OKF v0.2 兼容 bundle（trust 字段族、stale_after、human: 前缀人审标记）

### 2.2 读书/学习领域 schema（v1 旗帜）

| 页面类型 | 内容 | 对应学习行为 |
|---|---|---|
| 作品卡 | 一书/一论文的元信息、结构、读书进度 | 读什么 |
| 章节摘要 | 逐章/逐篇要点（严格引用） | 读了什么 |
| 概念卡 | 一概念一张卡：定义、谱系、跨书分歧 | 学到了什么 |
| 人物卡 | 作者/人物：观点、立场、影响 | 谁说的 |
| 主题页 | 跨源综合："三本书如何论述 X" | 连点成面 |
| 分歧页 | 显式记录矛盾："A 说 X，B 说 ¬X（来源各标注）" | 批判性阅读 |
| 复习卡 | 从概念卡衍生的间隔复习项 | 记住了什么 |

- 断言生命周期：ADD / REVISE / DEPRECATE + 有效期；矛盾显式建模不强行调和
- 引用一律工具生成的指针（file:span），模型不得自由生成引用

### 2.3 渐进结构化（P2，对普通用户最重要的决策）

```
阶段 0「堆」     ≤50 条：零 schema 压力，只管捕获（乱但存在 > 永远不写的完美）
阶段 1「命名」   ~100 条：提示开启命名规范 + 常青/易变隔离
阶段 2「约定」   ~300 条：约定回本（token 成本/新鲜度/冲突），lint 全面介入
阶段 3「分域」   跨领域：每领域子 schema，顶层只留通用规则
```

## 3. 操作面

### 3.1 CLI 命令

| 命令 | 行为 |
|---|---|
| `kb init` | 脚手架 vault（中文默认，OKF 兼容） |
| `kb ingest <src>` | 解析→入 raw→生成编译计划→**人审队列**→原子应用 |
| `kb query <q>` | 三级渐进披露（目录→单行摘要→按需打开）→FTS 兜底→引用作答→答案可写回（带防火墙） |
| `kb lint` | 死链/近似重复/矛盾/过期扫描 → **决策队列**（每条有 owner/状态/批量裁决），绝不自动建 stub |
| `kb review` | 审批待定动作（action 粒度 checkbox，plan 短过期） |
| `kb status / metrics` | 每查询 token、ingest 成本、已编译知识命中率、源/编译页比率（<1 警报） |

### 3.2 MCP server

同一引擎暴露为 MCP tools（ingest / query / lint / review / read_page / search），供 Claude Code、Codex、Cursor、OpenCode 等任意 agent 客户端复用——**vault 是资产，MCP 是接口，CLI 是人用入口**。

### 3.3 写路径（P0，信任是一切的前提）

```
受约束 completion（结构化输出）
  → 封闭动作词表校验（JSON Schema，"缺失的 enum 是墙"）
  → executor 原子应用（快照→临时→rename；400 行上限+溢出指针）
  → 人工批准（action 粒度）→ 落盘 + git commit
```

- raw 层从动作枚举上**不可达**
- 一切审计发现强制带 8-300 字符逐字引用，runner 重读磁盘核验
- 源文件内嵌指令 = 不可信内容（prompt injection 防护）
- 聊天不是源：先落文件再引用

### 3.4 查询路径

- 三级渐进披露 + 语义化可预测路径（降成本 33-50%，质量不降）
- wiki 为主、FTS 兜底（SQLite FTS5）；声称"不知道"前强制全文搜索
- 永不向用户展示模型 confidence 当信任信号——用引用核验替代
- ingest 带 CEGAR 探针：每源生成"应能答出"的诊断问题，编译后验证，丢失强制补回

## 4. 技术选型（待确认）

| 项 | 推荐 | 理由 | 备选 |
|---|---|---|---|
| 语言 | **Python 3.12+ / uv** | 文档解析生态决定性（markitdown/docling/ebooklib/EPUB）；官方 MCP SDK 成熟；uvx 一键运行；社区先例最多，中文贡献者友好 | TypeScript（npm 分发/Claude 生态亲和）、Rust（单二进制但慢）、Go |
| 存储 | git + SQLite（FTS5） | wiki=纯 markdown 可携带；索引可丢弃可重建 | 纯文件索引 |
| 模型接口 | OpenAI-compat 统一 + Anthropic 原生 | 一个接口覆盖 DeepSeek/GLM/Qwen/Moonshot/OpenRouter/**Ollama 本地**/vLLM | |
| 路由策略 | 小模型做决策路由 + 大模型做综合 | crow-hq 实证：ingest 72% token 花在"决定"而非"写作"；分类器接管后成本减半、精度反升 | 单模型 |
| 渲染 | 推荐 Obsidian 作为查看器 | Karpathy 原模式即如此；不重复造 graph view | 内置 web view（v0.2+） |

## 5. MVP 范围（v0.1）

**做**：init / ingest（PDF·EPUB·MD·URL）/ query / lint（决策队列）/ review / metrics / MCP server / 中文读书 schema 模板 / git 版本化 / OKF 兼容导出

**不做（明确出界）**：GUI、移动端、协作/多用户、向量检索（FTS 兜底先行，~100k token 热内容再加）、间隔复习引擎（v0.2）、播客/视频转写（v0.2）、自动网络抓取（保持人筛源的 Karpathy 原则）

**成功标准**（北极星，从第一天埋点）：
1. 每查询 token（对比裸 RAG 基线）
2. 已编译知识命中率（复用率——成本回本的直接变量）
3. 决策队列吞吐（决策债是否在消化而非累积）
4. 源/编译页比率 > 1（写快于读警报）

## 6. 路线图

- **v0.1**：引擎 + CLI/MCP + 中文读书 schema（本提案范围）
- **v0.2**：FSRS 复习卡、播客/视频源、领域模板扩展（行业研究型）
- **v0.3**：GUI 桌面壳（Tauri）——引擎不动，包壳服务普通用户
- 持续：评估记分卡（同域差分 + 人工抽检，绝不用绝对 LLM-judge 分数对外宣传）
