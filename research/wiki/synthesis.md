# 调研综合报告：结论与设计启示（2026-11-04）

> 综合来源：`wiki/landscape.md`（全景）+ 三份深挖笔记（`raw/deep-dive-*.md`）+ gist 评论区分析。
> 本文只写**结论与决策**；证据细节与出处见各原始笔记。

## 一、一句话结论

LLM Wiki 模式已被验证有效、标准已被 OKF 收敛、工具层已是红海；但**"面向普通用户（尤其中文）+ 本地优先 + 人机协作策展"的产品层完全空缺**——这既是 Karpathy 模式的本意，也是我们项目的定位空间。模式的三个核心风险（查询成本、结构性衰减、维护决策债）都有已验证的缓解手段，可以也应该作为产品能力内建。

## 二、证据调和：wiki 什么时候赢、什么时候输

三条独立证据流交叉后，胜负边界清晰且互相印证：

**wiki 赢的场景**（多方独立验证）：
- 跨源综合题：LangChain 111 文档 0.10→0.52（5x）；运维者原话"没有别的东西接近"
- 实体唯一真相源："每天都在回本的无聊模式"，改一处全局生效
- 快变小众领域时效：wiki 加一手 system cards 胜过前沿模型的过期知识
- 有纪律时的降幻觉：400+ 页 0 硬性矛盾——"结构让矛盾无处可活"
- 人类留存：可浏览的渲染（graph/Quartz）决定人是否回流

**wiki 输的场景**（同样多方验证）：
- 短/直接事实查询：13 题 A/B 全输（token ×9.3、p50 ×2.5）——检索型问题 1.4k token 够，wiki 路径吃 10-15k
- 开放式未见问题的细节检索（hyunsoo36 批评）：编译时不知未来问题，摘要可能恰好略去所需细节
- 数据不完备时：结构完美不补数据洞，反而产生"自信的错误"
- 无人执行策展决策时：10 周遥测死链 109→146 从未下降；lint 检测 ≠ 修复

**成本真相**：
- 体力维护被 agent 吸收（490 页稳态 = 每天 5 分钟 + 周日 45 分钟）
- 真实成本是**决策债**（死链分诊、实体成卡、矛盾仲裁、品味判断），累积速度 ≈ 新名字进入速度，按周复利
- 查询成本有三个**可叠加**的已验证杠杆：①查询路径设计（渐进披露降 33-50%，路由使 LLM 调用 O(1)）②已编译知识复用（答案写回省 84.6%）③serving 方式（避免自由浏览）
- 编译本身不贵（$4.15/111 文档全量、$0.09/篇增量）；"贵"的是无杠杆设计下的查询路径

**结论**：产品不应做 either/or（wiki vs RAG），而应做**分层路由**——编译层做权威与综合，检索层兜底细节问题，答案写回让探索复利（带防火墙）。

## 三、生态格局与我们的定位

1. **标准**：格式层跟随 OKF v0.2（Google 制定、LangChain 默认输出、免费接入其消费端生态），不自造格式；操作语义层（ingest/query/lint 行为）目前无标准——**不必抢标准位，做事实兼容即可**
2. **竞争**：工具层 150+ 项目红海（CLI/skill/MCP 同质化）；产品层蓝海。最接近的三个玩家都错位：WeKnora（36.4k★）重企业、无 OKF、轻量个人场景错配；OpenWiki（17.7k★）纯开发者向、无中文产品化；微软 llmwiki 绑 VS Code + Copilot
3. **学术空白** = 产品机会（论文侧原话）："普通用户 / <1000 源小规模 / 本地优先 / 人机 curation 工作流**完全没人做**"
4. **护城河候选**：领域 schema 模板库（横评结论"schema 是产品的 80%"）+ 渐进结构化路线（对普通用户最重要的产品决策）+ 确定性信任层（cite-and-verify 全行业收敛但无人在"普通人可用"形态下交付）

## 四、设计约束（证据→架构的映射，按优先级）

以下各项都有多个独立来源的验证支撑，应在设计阶段**作为约束而非选项**对待：

**P0 写路径信任**（MindBase 规则 + OKF trust 字段 + 多项目趋同）
- LLM 永不直接写散文：受约束 completion → 封闭动作词表（schema 校验）→ executor 应用
- raw 层从 schema 上**不可达**（"缺失的 enum 变体是墙"）
- 原子写 + 快照回滚 + 页面上限 + 溢出指针
- 一切审计发现强制带逐字引用、服务端核验——这是"agent 审计 agent"幻觉的唯一已验证解
- 人工批准以 action 为粒度、plan 短过期

**P1 维护 = 决策队列**（10 周遥测的直接产品化）
- lint 报告做成**分诊队列**（每条有 owner/状态/可批量裁决），不是计数仪表盘
- 绝不自动建 stub 清零死链
- "监控监控者"（lint 自报扫描基数与时间戳）

**P2 渐进结构化路线**（对普通用户最关键的产品决策）
- Pile 起步：≤50 笔记零 schema 压力，捕获习惯优先于结构完美
- ~100 笔记提示 schema；~300 约定回本；顺序：命名规范 → 常青/易变隔离 → 出处戳
- 跨领域拆子 schema；领域 schema 模板库是护城河

**P3 数据流架构**（三篇论文 + 社区独立收敛的同构分层）
- 不可变 raw（内容寻址）→ 带 source 坐标的中间层 → 可丢弃索引 → append-only 声明层（wiki）
- **单向流防火墙**：wiki 输出（origin: derived）永不当来源、排除出主索引（防自引用投毒，~1000 文件崩坏的根因）
- 断言生命周期：ADD/REVISE/DEPRECATE + 有效期；矛盾显式建模不强行调和
- 引用必须是工具生成的指针/锚点，模型不得自由生成引用

**P4 并发与接口**（Dexio 实测 + 社区趋同）
- 不做"每次 ingest 重写的全局文件"（index.md/log.md 是写热点）：description 入 frontmatter、历史入页面历史、写带 base_version
- index.md 降级为可选兼容层
- MCP server 内置（跨 agent 共享 vault 已是新项目默认）

**P5 查询与规模**
- 三级渐进披露（目录→单行摘要→按需打开）+ 语义化可预测路径
- wiki 为主、检索兜底；声称"不知道"前强制全文搜索；永不向用户展示模型 confidence 当信任信号
- 规模阈值内置于路线图：~100k token 热内容加分片/检索层；~10k 页是关键词搜索上限
- 周期性收缩（consolidation）作为官方正面操作（"页数只涨 = 没人打理"）

**P6 度量与评估**（从第一天埋点）
- 北极星候选：每查询 token、ingest 成本、已编译知识命中率、源/编译页比率（<1 警报）
- 评估对外**只用同域差分 + 人工抽检**——裁判间一致性 rho=0.04、LLM-as-judge 有知识混淆、一篇负面结果论文已撤稿，绝对分数在本领域不可信

**P7 安全**
- 源文件内嵌指令 = 不可信内容（prompt injection 经阅读清单进入是已证攻击面）
- 聊天不是源：先落文件再引用

## 五、风险清单

| 风险 | 等级 | 缓解 |
|---|---|---|
| 开放式问题细节缺失（hyunsoo36）| 高 | 分层语料（raw 永远可直接检索）+ 混合检索兜底 + 渐进结构化 |
| 维护决策债拖垮普通用户 | 高 | 决策队列产品化 + 领域模板降低策展门槛 + 明示"5 分钟/天"契约 |
| 无法对外证明效果（评估危机）| 中 | 同域差分评估内置为产品能力（记分卡：冷启动问题集） |
| 大厂挤压（腾讯转个人向 / LangChain 中文化）| 中 | 先发 + 深耕中文领域模板 + 本地优先隐私立场 |
| 做成"又一个 CLI 编译器"同质化 | 中 | 坚守产品层定位，复用而非重建工具层 |
| 论文结论波动（已有撤稿）| 低 | raw 笔记保留出处与时效戳，定期 lint 调研结论 |

## 六、留给设计阶段的讨论题（需要你拍板）

1. **目标用户画像**：中文普通用户太宽——首选场景是？（a）读书/学习型（b）行业研究/工作型（c）个人生活记录型（d）学生备考型
2. **产品形态**：桌面应用（Tauri 生态最成熟，Nash Su/llm_wiki 先例）/ 自托管 Web / 移动捕获+桌面消费？
3. **与终端 agent 的关系**：纯独立产品，还是同时提供 MCP/skill 供 Claude Code 等复用？（建议：两者，MCP 成本低）
4. **模型策略**：BYOK 云 API / 本地 Ollama / 混合路由？（中文用户对本地化的期待与模型能力存在张力）
5. **差异化主线排序**：渐进结构化、中文领域模板、信任层、人类留存（渲染/图）——哪个是 v1 的旗帜？
6. **命名、许可证**（社区主流 MIT/Apache-2.0，AGPL 用于托管类）、仓库与发布节奏
